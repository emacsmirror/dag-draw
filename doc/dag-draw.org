Dag Draw is an Emacs Lisp library for drawing directed acyclic graphs
(DAGs) using the GKNV hierarchical layout algorithm --- the same method
that powers Graphviz's ~dot~.  You declare which nodes connect to which;
dag-draw decides where everything goes and renders the result as ASCII
art, SVG, or Graphviz DOT.

This manual is for Dag Draw version 1.0.0.  It is organized along the
four Diataxis documentation quadrants: /Tutorials/ teach, /How-To Guides/
solve specific tasks, /Reference/ states the facts, and /Explanation/
discusses the ideas.

* Introduction
:PROPERTIES:
:DESCRIPTION: What dag-draw is and when to reach for it.
:END:

A /directed acyclic graph/ (DAG) is a set of nodes connected by one-way
edges with no cycles: dependencies, prerequisites, build orders, and
workflow steps are all DAGs.  Drawing one by hand is tedious --- you move
boxes around, untangle arrows, and start over when you run out of room.

Dag Draw removes that work.  You describe the /structure/ (what connects
to what); it computes the /layout/ (where each node sits and how each
edge is routed) using the GKNV algorithm from the paper /A Technique for
Drawing Directed Graphs/ by Gansner, Koutsofios, North, and Vo --- the
algorithm behind Graphviz.  The result is a clean, top-to-bottom
hierarchical drawing.

Every drawing follows the same three steps:

1. *Build* a graph, by mutating an empty one or from a declarative spec.
2. *Lay out* the graph, which assigns ranks, orders nodes to reduce edge
   crossings, and computes coordinates and edge routes.
3. *Render* the graph to ASCII, SVG, or DOT.

Dag Draw works on acyclic graphs.  If you hand it a graph with cycles,
you can find the offending edges with ~dag-draw-detect-cycles~ (see
[[*Detecting Cycles]]).

* Installation
:PROPERTIES:

Dag Draw requires Emacs 26.1 or later and the ~dash~ and ~ht~ packages.

(add-to-list 'load-path "/path/to/dag-draw.el")

** Your First Graph
:PROPERTIES:
:DESCRIPTION: Build, lay out, and render step by step.
:END:

In this tutorial we will draw a small workflow with a branch and a merge,
and render it as ASCII art in the terminal.  By the end you will have a
finished drawing and will understand the build/lay-out/render rhythm that
every dag-draw program follows.

*Prerequisites.* Dag Draw installed and loadable (see [[*Installation]]).

*Step 1: Create an empty graph.*

#+begin_src emacs-lisp
(require 'dag-draw)
(setq g (dag-draw-create-graph))
#+end_src

~g~ now holds an empty graph that we will fill in.

*Step 2: Add nodes.* Each node has an /id/ (a symbol you use to refer to
it) and a /label/ (the text shown in the box).

#+begin_src emacs-lisp
(dag-draw-add-node g 'design "Design")
(dag-draw-add-node g 'build  "Build")
(dag-draw-add-node g 'test   "Test")
(dag-draw-add-node g 'ship   "Ship")
#+end_src

*Step 3: Connect the nodes.* An edge points from one node id to another.
Here, ~design~ fans out to both ~build~ and ~test~, which both feed into
~ship~.

#+begin_src emacs-lisp
(dag-draw-add-edge g 'design 'build)
(dag-draw-add-edge g 'design 'test)
(dag-draw-add-edge g 'build  'ship)
(dag-draw-add-edge g 'test   'ship)
#+end_src

*Step 4: Lay out the graph.*

#+begin_src emacs-lisp
(dag-draw-layout-graph g)
#+end_src

This is where the algorithm runs.  It places ~design~ at the top, ~ship~
at the bottom, the two middle nodes side by side, and works out how to
route the edges.

*Step 5: Render it.*

#+begin_src emacs-lisp
(princ (dag-draw-render-graph g 'ascii))
#+end_src

You should see exactly this:

#+begin_example
┌────────┐
│ Design │
└────┬───┘
     │
     ├─────────────┐
┌────▼──┐      ┌───▼───┐
│ Build │      │ Test  │
└───┬───┘      └───┬───┘
    │              │
    ├──────────────┘
┌───▼───┐
│ Ship  │
└───────┘
#+end_example

*What you've built.* You described four nodes and four edges; dag-draw
chose the positions, split the edge out of ~Design~ with a ~├~ junction,
routed it around the boxes, drew ~▼~ arrowheads at the destinations, and
merged the two incoming edges of ~Ship~.  You never specified a single
coordinate.

To declare a whole graph in one form instead of mutating it node by node,
continue to [[*Building from a Spec]].  To understand what the lay-out
step actually does, see [[*The GKNV Layout Passes]].

** Building from a Spec
:PROPERTIES:
:DESCRIPTION: Declare a whole graph at once.
:END:

In this tutorial we will build a graph from a single declarative
specification with ~dag-draw-create-from-spec~, and add a couple of
visual touches.  This is the style integrators prefer: the whole graph is
data.

*Step 1: Write the spec.* A spec is a property list with ~:nodes~ and
~:edges~.  Each node is ~(id :label "..." ...attrs)~; each edge is ~(from
to ...attrs)~.

#+begin_src emacs-lisp
(setq g
      (dag-draw-create-from-spec
       :nodes '((research :label "Research")
                (design   :label "Design" :ascii-marker "* ")
                (build    :label "Build")
                (review   :label "Review" :ascii-highlight t)
                (ship     :label "Ship"))
       :edges '((research design)
                (design build)
                (build review)
                (review ship))))
#+end_src

Two visual attributes appear here: ~:ascii-marker~ prepends a string to a
node's label, and ~:ascii-highlight~ draws the box with double lines.
(See [[*Node Attributes]] for the full list.)

*Step 2: Lay out and render.*

#+begin_src emacs-lisp
(dag-draw-layout-graph g)
(princ (dag-draw-render-graph g 'ascii))
#+end_src

The result:

#+begin_example
┌──────────┐
│ Research │
└─────┬────┘
      │
      │
┌─────▼──┐
│* Design│
└────┬───┘
     │
     │
┌────▼──┐
│ Build │
└───┬───┘
    │
    │
╔═══▼════╗
║ Review ║
╚════╦═══╝
     │
     │
┌────▼──┐
│ Ship  │
└───────┘
#+end_example

Notice the ~* ~ marker on ~Design~ and the double-line box around
~Review~.

*What you've built.* You created a five-node pipeline from one data
structure --- no imperative ~add-node~/~add-edge~ calls.  Because the spec
is just a plist, it is easy to generate programmatically, which is how
packages such as org-gtd integrate dag-draw.

To highlight a node at render time instead of in the spec, see
[[*Highlighting a Node]].  For the full spec grammar and validation
rules, see [[*Constructing Graphs]].

** Querying a Graph
:PROPERTIES:
:DESCRIPTION: Inspect structure without rendering.
:END:

You can inspect a graph without laying it out or rendering it.  These
queries work as soon as the nodes and edges exist.

#+begin_src emacs-lisp
(setq g (dag-draw-create-from-spec
         :nodes '((a :label "A") (b :label "B") (c :label "C"))
         :edges '((a b) (a c) (b c))))

(dag-draw-node-count g)            ; => 3
(dag-draw-edge-count g)            ; => 3
(dag-draw-get-node-ids g)          ; => (c b a)
(dag-draw-get-successors g 'a)     ; => (c b)
(dag-draw-get-predecessors g 'c)   ; => (b a)
(dag-draw-get-source-nodes g)      ; => (a)
(dag-draw-node-label (dag-draw-get-node g 'a))  ; => "A"
#+end_src

~dag-draw-get-source-nodes~ returns the nodes with no incoming edges ---
the roots of the DAG.  For every edge in the graph, use
~dag-draw-graph-edges~; for the edges touching one node, use
~dag-draw-get-edges-from~ or ~dag-draw-get-edges-to~.

See [[*Querying]] for the complete list of query functions.

** Detecting Cycles
:PROPERTIES:
:DESCRIPTION: Find the edges that make a graph cyclic.
:END:

Dag Draw is meant for /acyclic/ graphs.  If a graph might contain a
cycle, ~dag-draw-detect-cycles~ tells you which edges close one: it
returns the back-edges (as edge structures), or ~nil~ if the graph is
acyclic.

#+begin_src emacs-lisp
(setq g (dag-draw-create-from-spec
         :nodes '((a :label "A") (b :label "B") (c :label "C"))
         :edges '((a b) (b c) (c a))))

(mapcar (lambda (e)
          (list (dag-draw-edge-from-node e)
                (dag-draw-edge-to-node e)))
        (dag-draw-detect-cycles g))
;; => ((c a))
#+end_src

On an acyclic graph the same call returns ~nil~:

#+begin_src emacs-lisp
(dag-draw-detect-cycles
 (dag-draw-create-from-spec
  :nodes '((a :label "A") (b :label "B"))
  :edges '((a b))))
;; => nil
#+end_src

Use the reported edges to decide which to remove or reverse before laying
the graph out.  For why dag-draw insists on acyclicity, see
[[*Why DAG-only]].

** Highlighting a Node
:PROPERTIES:
:DESCRIPTION: Emphasize one node at render time.
:END:

To emphasize one node at render time --- for example, to show "you are
here" --- pass its id as the third argument to ~dag-draw-render-graph~.
In ASCII output the selected node is drawn with a double-line box and its
bottom port becomes ~╦~.

#+begin_src emacs-lisp
(setq g (dag-draw-create-from-spec
         :nodes '((a :label "Plan") (b :label "Code") (c :label "Test"))
         :edges '((a b) (b c))))
(dag-draw-layout-graph g)
(princ (dag-draw-render-graph g 'ascii 'b))
#+end_src

#+begin_example
┌───────┐
│ Plan  │
└───┬───┘
    │
    │
╔═══▼═══╗
║ Code  ║
╚═══╦═══╝
    │
    │
┌───▼───┐
│ Test  │
└───────┘
#+end_example

The same /selected/ argument also affects SVG (a glow effect) and DOT
(~style=bold~).  To bake the emphasis into the graph definition instead,
use the ~:ascii-highlight~ node attribute (see [[*Node Attributes]]).

** Modeling Branches and Merges
:PROPERTIES:
:DESCRIPTION: Draw fan-out and fan-in.
:END:

Fan-out (one node leading to several) and fan-in (several leading to one)
need no special syntax --- just add the edges.  Dag Draw draws the split
and merge junctions for you.

#+begin_src emacs-lisp
(setq g (dag-draw-create-from-spec
         :nodes '((a :label "Collect Data")
                  (b :label "Clean")
                  (c :label "Analyze")
                  (d :label "Report"))
         :edges '((a b) (a c) (b d) (c d))))
(dag-draw-layout-graph g)
(princ (dag-draw-render-graph g 'ascii))
#+end_src

#+begin_example
┌──────────────┐
│ Collect Data │
└───────┬──────┘
        │
    ┌───┴───────────┐
┌───▼───┐      ┌────▼────┐
│ Clean │      │ Analyze │
└───┬───┘      └────┬────┘
    │               │
    ├┬──────────────┘
┌───▼▼───┐
│ Report │
└────────┘
#+end_example

The ~┴~ marks where ~Collect Data~'s edge splits toward the two middle
nodes, and the bottom rows show the two edges merging into ~Report~.  For
how these junction characters are chosen, see
[[*Drawing ASCII Edges and Junctions]].

** Producing SVG Output
:PROPERTIES:
:DESCRIPTION: Render scalable web graphics.
:END:

Pass ~'svg~ as the format.  The result is a complete SVG document as a
string, which you can write to a file or embed in a web page.

#+begin_src emacs-lisp
(setq g (dag-draw-create-from-spec
         :nodes '((a :label "Start") (b :label "End"))
         :edges '((a b))))
(dag-draw-layout-graph g)
(with-temp-file "graph.svg"
  (insert (dag-draw-render-graph g 'svg)))
#+end_src

The document begins like this:

#+begin_example
<svg width="130.0" height="120.0" viewBox="-15.0 -35.0 130.0 120.0" xmlns="http://www.w3.org/2000/svg">
  <defs>
    <marker id="arrowhead" ...>
#+end_example

Node appearance is controlled by the ~:svg-*~ node attributes and by the
SVG configuration variables (see [[*Node Attributes]] and
[[*Configuration Variables]]).

** Producing DOT Output
:PROPERTIES:
:DESCRIPTION: Render Graphviz DOT source.
:END:

Pass ~'dot~ to emit Graphviz DOT source, which you can pipe to the ~dot~
command or any DOT-aware tool.

#+begin_src emacs-lisp
(setq g (dag-draw-create-from-spec
         :nodes '((a :label "Start") (b :label "End"))
         :edges '((a b))))
(dag-draw-layout-graph g)
(princ (dag-draw-render-graph g 'dot))
#+end_src

#+begin_example
digraph G {
  node [shape=box, style=filled, fillcolor=lightgray];
  edge [color=black];

  a [label="Start"];
  b [label="End"];

  a -> b;
}
#+end_example

** Tuning Spacing
:PROPERTIES:
:DESCRIPTION: Adjust separation and scale.
:END:

Spacing is controlled by configuration variables.  For ASCII output the
relevant ones are ~dag-draw-ascii-node-separation~ (horizontal gap
between neighboring nodes, in characters) and
~dag-draw-ascii-rank-separation~ (vertical gap between ranks, in rows).
Bind them around a render to change the density:

#+begin_src emacs-lisp
(let ((dag-draw-ascii-node-separation 10)
      (dag-draw-ascii-rank-separation 3))
  (dag-draw-layout-graph g)
  (dag-draw-render-graph g 'ascii))
#+end_src

For SVG, ~dag-draw-svg-coordinate-scale~ multiplies the coordinate
system.  See [[*Configuration Variables]] for every tunable and its
default.

** Reading Laid-out Coordinates
:PROPERTIES:
:DESCRIPTION: Get bounds and per-node positions.
:END:

After ~dag-draw-layout-graph~, each node carries its computed position
and the graph has a bounding box.  This is useful when you embed a
drawing in a larger canvas.

#+begin_src emacs-lisp
(setq g (dag-draw-create-from-spec
         :nodes '((a :label "A") (b :label "B"))
         :edges '((a b))))
(dag-draw-layout-graph g)

;; (min-x min-y max-x max-y)
(dag-draw-get-graph-bounds g)   ; => (0.5 -1.5 9.5 6.5)

(let ((n (dag-draw-get-node g 'a)))
  (list (dag-draw-node-rank n)      ; => 0
        (dag-draw-node-x-coord n)   ; => 5
        (dag-draw-node-y-coord n)   ; => 0
        (dag-draw-node-x-size n)    ; => 9.0
        (dag-draw-node-y-size n)))  ; => 3.0
#+end_src

See [[*Struct Accessors]] for every accessor.

** Modifying an Existing Graph
:PROPERTIES:
:DESCRIPTION: Remove nodes and edges.
:END:

Remove an edge with ~dag-draw-remove-edge~ and a node with
~dag-draw-remove-node~.  Re-run ~dag-draw-layout-graph~ afterward to
recompute positions.

#+begin_src emacs-lisp
(setq g (dag-draw-create-from-spec
         :nodes '((a :label "A") (b :label "B") (c :label "C"))
         :edges '((a b) (b c))))
(dag-draw-remove-edge g 'b 'c)
(dag-draw-remove-node g 'c)
(list (dag-draw-node-count g)    ; => 2
      (dag-draw-edge-count g))   ; => 1
#+end_src

* Reference
:PROPERTIES:
:DESCRIPTION: The complete, verified public API.
:END:

This chapter lists the complete, verified public API.  Function arguments
are shown in the order they are accepted; ~&optional~ and ~&rest~ mark
optional and rest arguments as in Emacs Lisp.

** Constructing Graphs
:PROPERTIES:
:DESCRIPTION: Create graphs and add nodes and edges.
:END:

- Function: dag-draw-create-graph &optional attributes ::
  Create and return a new empty graph.  ATTRIBUTES is an optional hash
  table of graph-level attributes.

- Function: dag-draw-create-from-spec &rest spec ::
  Create a graph from a declarative specification and return it
  /unlaid-out/; call ~dag-draw-layout-graph~ before rendering.  SPEC is a
  property list with two required keys:

  - ~:nodes~ :: A list of node specifications.  Each is ~(id :label
    "Label" ...attrs)~, where ID is a symbol and ~:label~ is required.
    Remaining keyword properties become node attributes (see
    [[*Node Attributes]]).
  - ~:edges~ :: A list of edge specifications.  Each is ~(from to
    ...attrs)~, where FROM and TO are node ids.  Remaining keyword
    properties become edge attributes (see [[*Edge Attributes]]);
    ~:weight~ and ~:label~ are recognized specially.

  Signals an error if ~:nodes~ or ~:edges~ is missing, if a node lacks
  ~:label~, if a node id is duplicated, or if an edge references an
  unknown node.

- Function: dag-draw-add-node graph node-id &optional label attributes ::
  Add a node to GRAPH and return the created node.  NODE-ID is a unique
  symbol.  LABEL is the display string (defaults to the symbol name).
  ATTRIBUTES is an optional hash table of node attributes.  The node is
  auto-sized to fit its label.

- Function: dag-draw-add-edge graph from-node to-node &optional weight label attributes ::
  Add an edge from FROM-NODE to TO-NODE in GRAPH and return it.  WEIGHT
  defaults to ~1~.  LABEL is an optional edge label.  ATTRIBUTES is an
  optional hash table; a ~min-length~ key sets the minimum rank span
  (default ~1~).

** Laying Out
:PROPERTIES:
:DESCRIPTION: Run the layout algorithm.
:END:

- Function: dag-draw-layout-graph graph &rest args ::
  Run the GKNV layout algorithm on GRAPH in place and return it.  This
  performs four passes: rank assignment, vertex ordering, coordinate
  positioning, and spline (edge route) generation.  ARGS accepts one
  keyword:

  - ~:coordinate-mode~ :: ~ascii~ (the default) produces compact integer
    coordinates suited to terminal output; ~high-res~ is a legacy
    high-resolution mode.

** Rendering
:PROPERTIES:
:DESCRIPTION: Produce ASCII, SVG, or DOT.
:END:

- Function: dag-draw-render-graph graph &optional format selected ::
  Render a laid-out GRAPH and return a string.  FORMAT is one of:

  - ~ascii~ :: Monospace Unicode box-drawing art.
  - ~svg~ :: A complete SVG document.
  - ~dot~ :: Graphviz DOT source.

  When FORMAT is omitted, ~dag-draw-default-output-format~ is used.
  SELECTED is an optional node id to emphasize: a double-line box in
  ASCII, a glow filter in SVG, ~style=bold~ in DOT.

** Querying
:PROPERTIES:
:DESCRIPTION: Inspect structure.
:END:

- Function: dag-draw-get-node graph node-id ::
  Return the node structure for NODE-ID, or ~nil~.

- Function: dag-draw-graph-edges graph ::
  Return the list of all edge structures in GRAPH.

- Function: dag-draw-get-edges-from graph node-id ::
  Return the list of edges whose source is NODE-ID.

- Function: dag-draw-get-edges-to graph node-id ::
  Return the list of edges whose target is NODE-ID.

- Function: dag-draw-find-edge graph from-node to-node ::
  Return the edge from FROM-NODE to TO-NODE, or ~nil~.

- Function: dag-draw-get-node-ids graph ::
  Return the list of all node ids.

- Function: dag-draw-node-count graph ::
  Return the number of nodes.

- Function: dag-draw-edge-count graph ::
  Return the number of edges.

- Function: dag-draw-get-successors graph node-id ::
  Return the list of node ids directly reachable from NODE-ID.

- Function: dag-draw-get-predecessors graph node-id ::
  Return the list of node ids that point directly to NODE-ID.

- Function: dag-draw-get-source-nodes graph ::
  Return the list of node ids that have no incoming edges.

- Function: dag-draw-get-graph-bounds graph ::
  Return ~(min-x min-y max-x max-y)~, the bounding rectangle of the
  positioned graph.  Call after ~dag-draw-layout-graph~.

- Function: dag-draw-detect-cycles graph ::
  Return the list of back-edges (edge structures) that close a cycle, or
  ~nil~ if GRAPH is acyclic.  See [[*Detecting Cycles]].

** Mutating
:PROPERTIES:
:DESCRIPTION: Remove nodes and edges.
:END:

- Function: dag-draw-remove-node graph node-id ::
  Remove the node NODE-ID from GRAPH.

- Function: dag-draw-remove-edge graph from-node to-node ::
  Remove the edge from FROM-NODE to TO-NODE from GRAPH.

** Struct Accessors
:PROPERTIES:
:DESCRIPTION: Read node, edge, and graph fields.
:END:

After layout, node fields hold the computed geometry.  These accessors
read node, edge, and graph fields.  Coordinates and ranks are ~nil~ until
~dag-draw-layout-graph~ has run.

- Function: dag-draw-node-label node ::
  Return the node's display label.

- Function: dag-draw-node-rank node ::
  Return the node's assigned rank.

- Function: dag-draw-node-x-coord node ::
  Return the node's x center coordinate.

- Function: dag-draw-node-y-coord node ::
  Return the node's y center coordinate.

- Function: dag-draw-node-x-size node ::
  Return the node's width.

- Function: dag-draw-node-y-size node ::
  Return the node's height.

- Function: dag-draw-edge-from-node edge ::
  Return the edge's source id.

- Function: dag-draw-edge-to-node edge ::
  Return the edge's target id.

- Function: dag-draw-edge-label edge ::
  Return the edge's label.

- Function: dag-draw-edge-weight edge ::
  Return the edge's weight.

- Function: dag-draw-graph-nodes graph ::
  Return the node hash table mapping id => node.

** Node Attributes

| ~:ascii-highlight~   | boolean   | Draw a double-line box in ASCII output.      |
| ~:svg-fill~          | CSS color | Box fill color in SVG.                       |
| ~:svg-fill-opacity~  | number    | Fill opacity in SVG.                         |
| ~:svg-stroke~        | CSS color | Border color in SVG.                         |
| ~:svg-stroke-width~  | number    | Border thickness in SVG.                     |
| ~:svg-text-color~    | CSS color | Label color in SVG.                          |
| ~:svg-tooltip~       | string    | Hover tooltip in SVG.                        |

** Edge Attributes
:PROPERTIES:
:DESCRIPTION: Attributes for edges.
:END:

Edge attributes are keyword properties after the ~from~/~to~ ids in a
spec edge.

| Attribute  | Type   | Effect                                                                                       |
|------------+--------+----------------------------------------------------------------------------------------------|
| ~:weight~  | number | Layout weight; higher pulls endpoints into straighter, shorter alignment (default ~1~). |
| ~:label~   | string | Text label associated with the edge.                                                         |

** Configuration Variables
:PROPERTIES:
:DESCRIPTION: Customizable defaults.
:END:

All of these are customizable with =M-x customize-group RET dag-draw
RET=.

- User Option: dag-draw-default-output-format ::
  The format used by ~dag-draw-render-graph~ when none is given.  One of

* Explanation
:PROPERTIES:
:DESCRIPTION: The ideas behind the tool.
:END:

These sections discuss the ideas behind dag-draw.  They are background
reading, not step-by-step instructions; for those, see the [[*Tutorials]]
and [[*How-To Guides]].

** The GKNV Layout Passes
:PROPERTIES:
:DESCRIPTION: What "lay out" actually does.
:END:

Dag Draw implements the four-pass hierarchical layout from Gansner,
Koutsofios, North, and Vo's /A Technique for Drawing Directed Graphs/.
~dag-draw-layout-graph~ runs the passes in order:

1. *Ranking* assigns each node to a horizontal level (its /rank/), so
   that every edge points downward by at least its minimum length.
   Sources end up near the top, sinks near the bottom.
2. *Ordering* permutes the nodes within each rank to minimize the number
   of edge crossings, using iterated median heuristics.  This is what
   keeps the picture from turning into spaghetti.
3. *Positioning* assigns concrete x (and y) coordinates, balancing nodes
   under their neighbors and keeping edges as straight as possible while
   honoring the separation settings.
4. *Spline generation* computes the route each edge takes between its
   endpoints, bending around intervening nodes.

Each pass is a well-defined optimization, which is why the output is
stable and deterministic for a given graph.  The trade-off the algorithm
makes throughout is the GKNV aesthetic priority: expose hierarchy, avoid
crossings, keep edges short and straight, and balance the drawing.

** Drawing ASCII Edges and Junctions
:PROPERTIES:
:DESCRIPTION: How the box-drawing characters are chosen.
:END:

ASCII rendering walks each edge across a character grid and chooses a
/semigraphic/ (box-drawing) character based on the local context --- the
start port, the body of the edge, direction changes, and points where
edges meet.  This is what makes the output read as connected lines rather
than disconnected dashes.

The notable cases are:

- *Ports.* Where an edge leaves the bottom of a box, the box border gains
  a ~┬~ (a ~╦~ for a highlighted or selected node) so the line visibly
  emerges from the node.
- *Arrowheads.* Where an edge enters its destination, a ~▼~ marks the
  incoming port.
- *Splits and merges.* Where one edge fans out, or several edges join, a
  ~├~ or ~┴~ junction connects them rather than leaving a gap or an
  overwrite.
- *Crossings.* Where two edges cross, the character ~┼~ is drawn so both
  lines remain legible.

You can see several of these in the branch-and-merge example (see
[[*Modeling Branches and Merges]]).

** Coordinate Modes
:PROPERTIES:
:DESCRIPTION: Why ASCII and high-res coordinates differ.
:END:

Dag Draw runs its geometry in one of two coordinate spaces.  The default,
~ascii~, uses compact integer-scale coordinates and tight separations
tuned so a drawing fits comfortably in a terminal.  The legacy ~high-res~
mode keeps the larger world coordinates the GKNV paper describes (where
node sizes run in the dozens to low hundreds of units).

The ASCII mode exists because terminal cells are coarse: roughly five
characters per inch versus the paper's seventy-two units per inch.
Scaling world coordinates straight down would collapse distinct nodes
onto the same cells, so ASCII mode instead works natively at grid scale.
For SVG and DOT the larger coordinate space is fine, and
~dag-draw-svg-coordinate-scale~ adapts it to pixels.

** Why DAG-only
:PROPERTIES:
:DESCRIPTION: The acyclicity assumption.
:END:

The layout makes sense only when edges have a consistent direction: the
ranking pass needs to push every edge downward, which is impossible if a
set of edges forms a cycle (some edge would have to point back up).  Real
hierarchies --- dependencies, prerequisites, build orders --- are
acyclic, so this is rarely a limitation in practice.

When a graph /might/ contain a cycle, dag-draw does not silently guess.
~dag-draw-detect-cycles~ (see [[*Detecting Cycles]]) reports the exact
back-edges that close cycles, using the GKNV depth-first edge
classification, so you can remove or reverse them deliberately before
laying the graph out.
